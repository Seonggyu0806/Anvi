## 1. 블록 편집기 공통화

**왜.** 웨이퍼 레시피도 die 레시피처럼 블록으로 짠다. die 탭의 편집기(팔레트 · 캔버스 · 속성 · 검증 · 열기/저장)를 웨이퍼 탭에 **복사하면**
한쪽만 고쳐지는 날이 온다. 교수님도 웨이퍼 에디터에서 die 에디터와 같은 캔버스 · 팔레트 · 속성폼 · 검증을 다시 쓴다.

**어떻게.** 판단과 화면을 **둘 다** 꺼냈다.

| 부품 | 맡는 것 |
|---|---|
| `GraphEditorViewModel` | 판단 전부 — 팔레트 · 블록 추가/잇기/복제/삭제 · 속성 · 검증 · 열기/저장 |
| `GraphEditorView` | 화면 — 판단에 붙기만 한다. 탭마다 다른 칸 하나(`SideContent`)만 비워 둔다(die 탭은 미리보기) |
| `GraphEditorSettings` | **탭마다 다른 것** — 노드 명부 · 팔레트 필터 · 컨텍스트 입력 · 시작 그래프 · 파일 종류 |

- 편집기는 무엇을 돌리는지 모른다. 그래프가 바뀌면 `GraphChanged` 를 알리고, die 탭이 그걸 받아 미리보기를 다시 돌린다
- 확대 · 이동은 화면만 아는 값이라, 편집기는 `FitRequested`(전체 보기 해 달라)만 알리고 화면이 한다

**확인.** 꺼내기 전과 뒤에 die 탭의 상태(블록 · 선 · 속성 칸 · 검증 문장 · 미리보기 결과)를 **전부 글자로 적어 비교**했다 — 같았다.
화면을 화면 밖에 띄워 그려진 컨트롤 수도 같았다.

## 2. 노드 캔버스 — Nodify

**왜.** 첫 편집기는 블록을 상자로 늘어놓고 "연결 추가" 콤보로 선을 이었다. 교수님 화면은 Nodify 캔버스에서 포트를 끌어 잇는다.

**어떻게.** 교수님과 같은 **Nodify 7.3.0**.

| Nodify 부품 | 우리 쪽 |
|---|---|
| `NodifyEditor` | 캔버스. 블록 목록(`Nodes`) · 선 목록(`Connections`) · 끌고 있는 선(`PendingConnection`)에 붙는다 |
| `Node` + `NodeInput` / `NodeOutput` | 블록 하나 + 왼쪽 입력 점 · 오른쪽 출력 점(`ConnectorViewModel`). 점의 화면 위치(`Anchor`)는 Nodify 가 써 준다 |
| `Connection` | 두 점 사이 곡선 |
| `PendingConnection` | 점에서 끌기 시작 → 다른 점에 놓기(`StartCommand` · `FinishCommand`) |

| 규칙 | 내용 |
|---|---|
| 잇기 | 어느 쪽에서 끌었든 **출력 → 입력** 으로 바로잡는다. 출력끼리 · 입력끼리 · 같은 블록 안 · 컨텍스트 블록으로 들어가는 선은 무시한다. "입력 점에는 선 하나" 는 `GraphOps` 가 지킨다(새 선이 옛 선을 갈아 끼운다) |
| 편집 이력 | `GraphHistory` — 구조가 바뀌기 **직전**의 그래프를 통째로 복사해 쌓는다(블록 · 선 추가 · 삭제 · 복제). 새 그래프를 열면 비운다. **속성 값 고치기는 기록하지 않는다** |
| 자동 배치 | `LayoutEngine.Layered` — 블록의 열 = 그 블록까지 **가장 긴 앞 경로**의 길이. 같은 열은 레시피 순서대로 위에서 아래. 왼쪽 열(x < 240)은 컨텍스트 블록 자리. 고리가 있어도 멈춘다. 열 간격 300 · 줄 간격 160 |
| 팔레트 | 명부에서 펼쳐 분류로 묶고(`ICollectionView`) 검색칸으로 거른다 |
| 색 | 블록 머리 = 분류 색(`CategoryToBrushConverter`) — 팔레트 묶음 머리와 같은 색. 검증 오류가 가리키는 블록은 빨간 테두리(검증 문장 앞머리 `node 'id'` 에서 찾는다) |
| 단축키 | Ctrl+Z / Ctrl+Y / Ctrl+D / Delete — **탭 안에서만** 듣는다. 창 전체에 걸면 다른 탭에서 눌러도 이 그래프가 바뀐다 |

- 지운 것: "연결 추가" 콤보, 격자로 늘어놓던 `GraphOps.AutoLayout`(→ `LayoutEngine`)
- 열 간격은 처음 260 이었다. 웨이퍼의 `InspectDies`(출력 셋 + 체크박스)가 옆 열에 닿아 B-1 에서 300 으로 늘렸다

**시험.** `GraphHistoryTests`(5) · `LayoutEngineTests`(5) — 화면 없이 그래프와 좌표만 본다.

## 3. 연결 해제 — 함정 둘

**정한 것.** 선을 **더블클릭** 또는 **Alt+클릭** 하면 끊는다. Nodify 기본은 Alt+클릭뿐이고, 더블클릭은 '선 나누기' 에 걸려 있다 — 우리는 선 나누기를 안 써서 풀었다.

처음엔 둘 다 안 됐다.

**함정 ① — 명령에 무엇이 넘어오나.** 선 자신의 `DisconnectCommand` 는 **누른 위치(Point)** 를 넘긴다(Nodify 설명서: *"Parameter is the location"*).
우리 명령은 선(`ConnectionViewModel`)을 받아야 해서 위치가 오면 조용히 무시했다.
→ 편집기의 `RemoveConnectionCommand` 에 걸었다. 이쪽은 **선의 DataContext** 를 넘긴다.
교수님 앱도 선 자신의 명령에 걸려 있어 같은 증상이 있을 수 있다.

**함정 ② — 언제 판정하나.** Nodify 의 끊기 손짓은 마우스를 **뗄 때** 판정한다(`ConnectionState.Disconnect.OnMouseUp`). 선 나누기는 **누를 때** 판정한다.
실제 더블클릭은 뗄 때 '두 번째 클릭' 으로 잡히지 않아, 손짓에 더블클릭을 걸어도 끝내 맞지 않았다. Alt+클릭은 뗄 때도 Alt 가 눌려 있어 맞았다.
→ 더블클릭은 Nodify 손짓에 맡기지 않고, 선을 **누를 때** 클릭 횟수를 직접 본다(`OnLineMouseDown`). 끊는 것은 Nodify 가 부르는 것과 같은 `Remove()` 라 되돌리기도 그대로다.

**배운 것.** 처음 화면 검사는 누를 때 · 뗄 때 둘 다 클릭 횟수 2 로 흉내 내서 통과했다 — 실제와 다른 조건이었다.
이제 검사는 실제 순서(누름 1 → 뗌 → 누름 2 → 뗌)로, 뗄 때 클릭 횟수 2 · 1 둘 다 본다.

## 4. 웨이퍼 레시피 편집기

**어떻게.** 탭 셋 — die 에디터 · **웨이퍼 에디터** · 웨이퍼(옵션으로 검사). 웨이퍼 에디터는 1절의 공용 편집기에 설정만 다르게 준다(`WaferEditorViewModel`).

| 설정 | 값 |
|---|---|
| 명부 | `WaferBackend` — Cv 블록 + 웨이퍼 블록 |
| 팔레트 | 웨이퍼 종류(표식 목록 · 자세 · 격자 · 웨이퍼 결함)를 주고받는 블록만 — die 탭과 반대 |
| 컨텍스트 입력 | `alignSrc`(웨이퍼 사진) · `alignTemplate`(표식 조각) |
| 시작 | 견본 `samples/wafer/demo.wafer.json` **파일로** 연다 — 안의 경로를 풀 폴더가 생긴다. 실행 폴더에서 위로 올라가며 `DiePipeline.slnx` 를 찾는다(시험과 같은 방법). 못 찾으면 빈 그래프 |

### 4.1 실행

```
합성 견본 그리기 / 사진 열기  →  ▶ 실행  →  요약 · 정렬 · 경고  +  웨이퍼 맵  +  결함 목록
```

- 레시피는 내보내기와 같은 길로 만든다(`ExportRecipe` — 검증 강제). 검증에 막히면 돌리지 않는다
- 실행기는 명령행 `--recipe` 와 **같은** `WaferRecipeRunner` 다. 화면 그래프는 아직 파일로 안 썼을 수 있어서 입구를 하나 더 냈다 —
  `RunIn(레시피, 폴더, …)`. `RunFile` 도 이제 이걸 거친다. 경로 규칙은 `PathIn(폴더, 경로)` 한 곳
- 백그라운드로 돌고 취소할 수 있다. 취소하면 결과를 버린다(반쯤 본 웨이퍼를 결과처럼 보이지 않게)
- 실패는 예외 이름이 아니라 문장으로 검증칸에 띄운다 — 예: "레시피 파일이 없습니다: …"
- 레시피를 고치면 "결과가 바뀌기 전 레시피의 것" 이라고 알린다. 웨이퍼 검사는 오래 걸릴 수 있어 저절로 다시 돌리지 않는다(die 탭 미리보기는 저절로 돈다)

**시험.** `편집기를_거친_견본은_파일과_같은_답` — 견본을 편집기 그래프로 바꿨다가 다시 레시피로 내보내 메모리에서 돌린 결과가, 파일로 돌린 결과와 정렬 · 결함 목록까지 같다.

### 4.2 웨이퍼 맵

교수님 웨이퍼 맵과 같은 모양 — die 하나가 칸 하나, 셀에 결함 수.

| 상태 | 색 | 언제 |
|---|---|---|
| E1 | 초록 | 유효 die, 결함 없음 |
| E0 | 청회 | 가장자리 die, 결함 없음 |
| 결함 | 빨강 | 결함이 있는 die(존과 상관없이) |
| 검사 실패 | 주황 · `!` | die 검사가 터졌다 — 결함 0개로 보이지만 안 본 것 |
| 원판 밖 | 옅은 회색 | die 가 아니다 |

- 칸 계산은 화면과 상관없어 웨이퍼 층에 뒀다(`WaferMap.Of`) — 시험이 칸 상태와 수를 지킨다(`WaferMapTests` 4)
- 칸의 결함 수는 **추리기 전**(`Found`) — 판정과 같은 것을 센다. 결함 목록은 추린 뒤(`Defects`). 그래서 Sampling 으로 1개만 남겨도 맵의 결함 칸은 그대로다
- **멈췄으면 맵을 안 그린다** — 빈 맵은 "깨끗한 웨이퍼" 로 읽힌다

### 4.3 저장 위치와 경로

레시피 안의 경로(die 레시피 · 표식 조각)는 **레시피 파일이 있는 폴더 기준**이다(6주차 §6.5). 그래서 편집기는 지금 그래프를 연 · 저장한 파일(`FilePath`)과 그 폴더(`Folder`)를 들고 있다.

**다른 폴더에 저장하면** 파일만 옮기고 경로를 그대로 두면 엉뚱한 곳을 가리킨다 — 화면에선 돌았는데 명령행으로는 안 도는 레시피가 된다.
→ `WaferRecipePaths.Rebase` 가 옛 폴더 기준 경로를 새 폴더 기준으로 고쳐 적는다.

| 규칙 | 내용 |
|---|---|
| 고치는 값 | `InspectDies` 의 `e1Recipe` · `e0Recipe` · `features[].template` 셋뿐 |
| 그대로 두는 것 | 절대 경로 · 빈 값 · 다른 블록 · 경로가 아닌 값 |
| 모양 | 슬래시(`/`)로 적는다 — 견본과 같고 윈도에서도 풀린다. 드라이브가 다르면 절대 경로 |
| 화면 쪽 | 저장한 뒤 화면 그래프도 고친 경로로 다시 연다(블록 위치는 그대로). 되돌리기 기록은 옛 폴더 기준이라 비운다 |

- 열기 · 저장은 대화상자와 실제 처리를 나눴다(`Open(path)` · `Save(path, recipe)`) — 화면 없이 검사할 수 있게
- 편집기는 경로를 모른다. 경로를 품은 레시피(웨이퍼)만 설정으로 `RebasePaths` 를 준다

**시험.** `WaferRecipePathsTests`(4) — 옮겨 적은 경로를 새 폴더에서 풀면 옛 경로를 옛 폴더에서 푼 것과 같은 파일이다. `다른_폴더에_옮겨_저장한_견본도_그대로_돈다` — 옮겨 저장한 견본을 명령행 입구로 돌려도 심은 결함을 다 찾는다.

### 4.4 화면 배치

- 실행 패널은 넓어야 해서(맵 + 결함 목록) 편집기 오른쪽 칸이 아니라 **편집기 아래**에 둔다(높이를 끌어 바꾼다)
- 오른쪽 아래 칸(`SideContent`)은 높이를 끼우는 쪽이 정한다 — die 탭 미리보기는 250, 웨이퍼 에디터는 안 끼운다
- 창 크기 1360 × 860

## 5. 복합 파라미터 편집

**왜.** 속성 칸은 블록 설명(서술자)에 적힌 **낱개 값**(숫자 · 글자 · 체크 · 고르기)만 그린다. 아래 넷은 목록 · 묶음이라 서술자로 못 적어서 화면에 아예 안 나왔다 — 레시피 파일을 손으로 고쳐야 했다.

| 블록 | 값 | 모양(`ListLayout`) | 칸 |
|---|---|---|---|
| `SolveAlignment` | `expected` 표식 설계 위치 | `[[x,y], …]` — Tuples | x · y |
| `InspectDies` | `features` 표식 템플릿 | `[{ "template" }]` — Objects, 순서 바꾸기 | 경로 |
| `InspectDies` | `circle` 원판 | `{ centerX, centerY, radius }` 또는 없음 — Single | 숫자 셋 + '씀' |
| `InspectDies` | `zones` 수동 존 지정 | `[{ col, row, zone }]` — Objects | 정수 둘 + E1 · E0 · off |

### 5.1 정한 것

| | 정한 것 | 다른 길 | 까닭 |
|---|---|---|---|
| 방식 | **전용 편집 칸**(교수님 방식) — 단 부품 하나(`ListParamViewModel`)를 넷이 같이 쓰고, 어느 값에 어떤 칸인지는 표 하나(`ListParams`) | 서술자에 목록 · 묶음 모양을 적고 편집기가 알아서 그린다 | 목록 값이 넷뿐이라 서술자 · 검증기 · 속성폼 모델까지 키울 값어치가 없다. 새 값은 표에 한 줄 |
| 값 검사 | 블록 팩토리(`ICustomParamsValidator`)가 그대로 한다 — 고치는 즉시 검증칸 | 편집 칸이 따로 검사 | 규칙이 두 곳이면 어긋난다 |
| 되돌리기 | 기록하지 않는다(낱개 값과 같다) | 행 추가 · 삭제만 기록 | 낱개 값과 규칙이 달라지면 헷갈린다 |
| 입구 블록 | 누르면 안내 한 줄. `alignTemplate` 은 `InspectDies` 의 표식 템플릿 칸을 **같은 칸**으로 보여 준다 | 아무것도 안 보인다 | 어느 쪽에서 고쳐도 한 값이 바뀐다 |

### 5.2 글자 ↔ 값

`ListParams` 가 행(칸 글자들)과 JSON 값을 오간다. 화면과 상관없어 편집기 층에 두고 시험한다(`ListParamsTests`).

- **읽기** — 모양이 어긋난 행도 읽을 수 있는 칸만 채워 보여 준다. 버리면 사람이 고칠 기회도 없다. 고르는 칸은 고를 수 있는 글자로 맞춘다(`e1` → `E1`)
- **쓰기** — 숫자 칸을 하나라도 못 읽으면 **안 쓴다**. 치는 중인 빈 칸 · 잘못 친 글자를 0 으로 쓰지 않는다(낱개 값 칸과 같은 규칙)
- **묶음 하나**(원판)는 행이 없으면 레시피에서 **뺀다**
- 아는 칸만 쓴다 — 우리 레시피 형식에는 다른 칸이 없다
- ★ 시험 `쓴_값은_블록_검사를_통과한다` — 편집 칸이 쓰는 모양과 블록 팩토리가 받는 모양이 같은지 본다. 한쪽만 바뀌면 고칠 때마다 빨간 줄이 뜬다

### 5.3 경로 칸

- 서술자에 `IsPath` 를 더했다 → 속성 칸 종류 `FieldControl.Path`(입력칸 + 찾아보기). `e1Recipe` · `e0Recipe` 에 붙였다. 검증은 글자 그대로
- 찾아보기로 고른 파일은 **레시피 폴더 기준 상대 경로**로 적는다(`EditorPaths.Relative`). 저장 안 한 레시피 · 다른 드라이브는 절대 경로
- 속성 칸은 편집기에 두 가지만 묻는다 — 기준 폴더 · 파일 고르기(`FieldServices`). 파일 고르기는 대화상자라, 화면 없이 검사할 때 바꿔 끼운다(`PickFile`)

### 5.4 탭을 처음 열 때 화면 맞추기

**증상.** 웨이퍼 에디터 탭을 처음 열면 캔버스가 가장 작게(0.1배) 줄어 있거나 맞춰지지 않았다. '전체 보기' 를 누르면 제대로 됐다(B-1 부터).

**원인 둘.**
- 탭이 아직 안 보여 캔버스 크기가 0 일 때 맞추기가 먼저 돌았다 — 화면 크기 0 ÷ 그래프 크기 = 0 → 최소 배율
- 탭이 보이는 순간 Nodify 가 잠깐 확대를 막아 둔다(`DisableZooming = true`). 그때의 맞추기는 Nodify 가 무시한다(`ZoomAtPosition` 이 확대 금지면 아무것도 안 한다)

**고침.** '맞춰야 함' 만 적어 두고, **보이고 · 크기가 있고 · 확대 금지가 풀렸을 때** 한 번 맞춘다. 크기 변화 · 보임 변화 · 확대 금지 변화를 받을 때마다 다시 본다.
이제 탭을 열면 0.4초 안에 '전체 보기' 와 같은 배율로 맞춰진다.

## 6. 화면 검사 방법

WPF 화면은 단위 시험에 안 들어간다. 대신 **레포 밖 검사 프로그램**으로 확인했다(레포에는 안 넣었다).

| 무엇 | 어떻게 |
|---|---|
| 뷰모델 조작 | 화면 없이 뷰모델 명령을 직접 부른다 — 끌어 잇기 · 끊기 · 되돌리기 · 실행 · 행 추가 · 찾아보기(파일 고르기를 바꿔 끼움) |
| 그려진 것 세기 | 창을 화면 밖(-20000, -20000)에 띄우고 시각 트리에서 블록 · 선 · 칸 · 버튼 수를 센다 |
| 바인딩 오류 | `PresentationTraceSources` 로 바인딩 경고를 모은다 — 매번 0개 |
| 그림 | `RenderTargetBitmap` 으로 창을 그림으로 떠서 눈으로 본다(합성 견본만) |
| 마우스 | 실제 순서로 흉내 낸다(3절 배운 것) |

- 고친 것은 **고치기 전 상태에서 증상이 재현되는지** 먼저 보고, 고친 뒤 없어지는지 본다 — 선 끊기 · 화면 맞추기 모두 그렇게 확인했다
- 마지막은 사람이 실제 화면에서 확인한다
