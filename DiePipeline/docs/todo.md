### 3-1. 실데이터 시험 — 정한 것 (2026-10-06)

손으로 쳐서 눈으로 본 실데이터 결과를 **시험으로 굳힌다.** 교수님 `WaferRealDataTests`(Phase8 8.7)와 같은 방식 —
원본이 있는 컴퓨터에서만 돌고, 없으면 조용히 통과. 비교는 **허용오차**(완전일치 금지).

| 어디 | 무엇 |
|---|---|
| 레포 안 | 시험 코드만 — "폴더를 주면 그 설정으로 검사하고 기준과 허용오차 비교" |
| 레포 밖(사진 옆) | 설정 파일 · 기준 결과 파일 — 원본 경로 · 격자 · 피치 · 원판이 들어간다 |
| 연결 | 환경 변수 하나(예: `DIEPIPE_REALDATA`)가 그 폴더를 가리킨다. 없으면 건너뛴다 |

**순서는 §8 뒤.** 레포 밖 설정 파일은 결국 웨이퍼 레시피와 같은 내용이라, 같은 형식을 두 번 만들지 않는다.

## 8. 웨이퍼 레시피 — 입력을 파일 하나로 (2026-10-06 계획)

**계기.** 웨이퍼 탭에 격자 · 원판 · 표식 · 수동 지정을 매번 입력하는 것이 번거롭다 → [deferred.md](deferred.md) §10 ② 의 넣을 조건이 됐다.

**교수님 방식.** ① 작업 파일 `*.job.json`(먼저 만듦, 지금은 "구 형식 — 하위호환") → ② 통합 블록 레시피 `*.wafer.json`(권장). **② 로 간다.**

```
[TemplateMatchAll] → [SolveAlignment] → [InspectDies] → [TransformAbs] → [Sampling]
 표식 찾기            자세 계산          die 전부 검사(경계)  웨이퍼 좌표로     결과 추리기
```

### 정한 것

| | 결정 |
|---|---|
| 표식 찾는 범위 | 실행기가 표식마다 **창을 잘라** 표식 찾기 블록에 넣고, 찾은 자리를 사진 좌표로 모아 자세 계산 블록에 넘긴다. 범위 0 = 사진 전체 한 번(교수님 Phase5 #5.10 — 창 읽기는 블록이 아니라 실행기의 일) |
| 표식 위치 | `SolveAlignment.expected` **에만** 적는다. 조각 경로는 `InspectDies.features[].template` 에만. 교수님 견본은 두 곳에 적는데, 떨어진 짝은 언젠가 어긋난다 |
| 키 이름 | 교수님 이름을 따른다. `edgeExclusionPx` = 원판 가장자리 여유(px), `edgeRings` = 테두리 겹 수. 우리에게만 있는 것: `circle` · `zones` · `searchPaddingPx` · `neighbors` · `dieWidth/Height` · `firstDieX/Y`(대략 원점) |
| 명령행 옵션 | 남긴다. **입구는 둘(옵션 · 레시피 파일), 속은 하나**(`WaferInspection` — 창 찾기 · 가드 · 격자 · die 반복). 화면은 die 레시피를 파일이 아니라 메모리로 들고 있어 레시피로 바꾸려면 가짜 경로가 필요했다. 두 입구가 같은 답인지는 시험으로 증명한다(`WaferRecipeRunnerTests`) |
| 합성 견본 | `samples/wafer/demo.wafer.json` + `samples/wafer/features/demo_mark.bmp` — 레포에 둔다(코드로 그린 그림) |
| 실데이터 레시피 | **레포 밖**(사진 옆)에 둔다 — 격자 · 피치 · 원판 위치가 들어간다 |
| 이미지 경로 | 레시피에 넣지 않는다. 실행할 때 따로 준다(교수님과 같음) |
