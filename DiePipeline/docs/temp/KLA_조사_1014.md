## 2. 제품 및 기술

### 2.1 칩 제조
- 첨단 논리 및 메모리(3D NAND, DRAM, MRAM 등), 전력반도체 소자, RF 통신 소자, LED, 광자학, MEMS 등의 광범위한 소자 유형을 위한 칩 제조를 지원
- 결함 검사 및 리뷰, 계측, 반도체 소프트웨어 솔루션 등

### 2.2 웨이퍼 제조
- 웨이퍼 제조 시스템은 실리콘, 프라임 실리콘, SOI, 사파이어, 유리, GaAs, SiC, GaN, InP, GaSb, Ge, LiTaO₃, LiNbO₃, 에피택셜 웨이퍼를 포함하여 광범위한 기판 유형 및 크기에 대한 공정 개발, 생산 모니터링 및 최종 품질 검사를 지원
- 결함 검사 및 리뷰, 계측, 반도체 소프트웨어 솔루션, 공정 중 공정 관리

### 2.3 레티클 검증
- KLA의 레티클 검사, 계측 및 데이터 분석 시스템 포트폴리오는 최첨단 광학 및 센서 기술과 알고리즘을 활용하여 블랭크, 레티클 및 칩 제조업체가 레티클 결함과 패턴 배치 오류를 식별하고 수율 위험을 낮출 수 있도록 지원

### 2.4 패키징 제조
- 방대한 패키징 솔루션 포트폴리오는 광범위한 패키징 응용 분야에서 외주반도체패키지테스트(OSAT), 소자 제조업체, 파운드리 및 IC 기판 제조업체의 제조 공정 속도를 단축
- 웨이퍼와 계측, 웨이퍼 공정 시스템, 다이 선별 및 검사, 인쇄회로기판 및 IC 기판 제조 등

### 2.5 인쇄회로기판 및 IC 기판 제조
- 첨단 공정 제어 및 공정 실행 솔루션은 인쇄회로기판(PCB) 및 집적회로 기판(ICS) 제조를 지원
- 패터닝용 다이렉트 이미징, 자동 광학 쉐이핑, PCB 소프트웨어 솔루션 등
- 2019년 인수한 Orbotech 사업이 이 부문(PCB and Component Inspection)에 해당 [4]

### 2.6 소프트웨어 솔루션
- **반도체 제조업체**: 개발 단계에서 모델링 및 설계를 수행하고, 생산 데이터를 수집하여 분석하기 위해 KLA의 소프트웨어 솔루션을 사용
- **PCB 제조업체**: CAM(Computer-Aided Manufacturing), 엔지니어링 및 전체 생산 과정의 데이터 분석에 KLA의 솔루션을 활용
- AI 기반 소프트웨어 솔루션을 통해 제조업체는 수율을 가속화하고 생산 품질을 개선
- 대표 제품
  - **Klarity®** (Klarity Defect, Klarity SSA, Klarity ACE XP): 검사·리뷰 데이터를 근본 원인 정보로 바꾸는 팹 전체 수율 솔루션 [19]. 웨이퍼 검사기에서 나온 데이터를 오프라인으로 분석하는 제품 [20]
  - **PROLITH™**: 레티클 패턴이 웨이퍼에 어떻게 찍힐지 예측하는 노광 시뮬레이터 [20]

### 2.7 OEM
- OEM(Original Equipment Manufacturers)은 웨이퍼, 레티클, 칩, PCB 등을 제조하는 데 쓰이는 시스템과 솔루션을 생산
- KLA의 검사, 계측, 화학 시스템은 공정 및 공정 장비 개발과 검증을 가속화할 수 있도록 지원
- 정전용량 센서, 공정 제어

### 2.8 기타 산업
- 반도체 공정 제어 제품을 기반으로 개조한 공정 제어 장비와 전략을 제공
- 대학 및 산업 연구, 하드 디스크 드라이브 제조, 태양광 제조

## 3. 공정 제어 기본 개념

### 3.1 검사(Inspection) · 리뷰(Review) · 계측(Metrology)
| 구분 | 질문 | 예시 장비 |
|---|---|---|
| 검사 | "어디에 결함 후보가 있나?" — 웨이퍼 전체를 빠르게 훑어 위치를 찾음 | 29xx/39xx, Puma |
| 리뷰 | "그게 정확히 뭔가?" — 찾은 위치를 고배율로 다시 보고 분류 | eDR 시리즈 |
| 계측 | "치수가 맞나?" — 선폭, 두께, 정렬 같은 수치 측정 | Archer, SpectraShape |

eDR7380은 광학 검사와 리뷰 사이에서 **스마트 샘플링과 결함 데이터 교환**으로 검사 감도를 높인다고 소개된다 [10].

### 3.2 결함 검출 방식
- **다이 대 다이(Die-to-Die)**: 검사 다이 이미지를 이웃 다이 이미지와 비교 [8]. 다이 대 다이·다이 대 데이터베이스가 로직 회로 검사의 주력 방식 [8]
- **이중 판정(Double Arbitration)**: 검사 다이를 양쪽 이웃 두 개와 각각 비교. 두 비교 모두에서 나온 결함은 검사 다이의 결함, 한쪽에서만 나온 결함은 기준 다이의 결함으로 판정 [16]
- **자기 비교(셀 대 셀)**: 같은 패턴이 반복되는 메모리 회로에서만 쓸 수 있는 방식 [8]
- **다이 대 데이터베이스(Die-to-Database)**: 실제 다이 이미지를 결함 없는 다이를 시뮬레이션한 이미지와 비교 [8]
- **다중 다이 자동 문턱값(MDAT)**: KLA가 제안한 검출 알고리즘. 여러 다이 정보로 **중간값(median) 이미지**를 만들어 기준으로 사용 [8]

### 3.3 광학 방식
- **명시야(Brightfield)**: KLA의 28xx 플랫폼이 명시야 검사 플랫폼 [12]. 광대역 플라즈마 광원은 283x(2835)에서 1세대가 시작돼 2900(2세대), 2920(3세대)으로 이어짐 [17]
- **암시야(Darkfield)**: 공간 필터로 반복 패턴을 지워 작은 파티클을 찾는 데 유리. 다만 회로 형상이 지워져 다이 정렬이 어려워서 명시야 이미지로 정렬 정보를 보완하기도 함 [16]. KLA의 Puma가 암시야 계열 [13]

### 3.4 핵심 용어
- **DOI (Defect of Interest)**: 수율에 영향을 주는, 실제로 찾고 싶은 결함
- **뉴슨스(Nuisance)**: 검출은 됐지만 수율과 무관한 가짜·무해 결함. 분류기 설정으로 뉴슨스 비율을 낮추는 것이 핵심 과제 [21]
- **비닝(Binning)**: 결함을 유형별 묶음(bin)으로 나누는 것. 현재 광학·전자빔 검사는 "이미지 차이로 검출 + 규칙 기반 비닝으로 분류"가 주류이고, 이 방식은 결함 종류·크기·기판 재질에 따라 유연하지 못하다는 한계가 지적됨 [8]

## 4. iDO (inline Defect Organizer)

### 4.1 개요
- **iDO는 2005년 2800 검사기에 처음 도입된 KLA의 인라인 자동 결함 비닝 소프트웨어** [12][18]
- 역할: 결함 모집단에서 **뉴슨스를 제거**하고, 남은 결함을 **유형별로 비닝** [18]
- 결함 속성(특징 벡터 등)을 활용해 뉴슨스를 자동으로 정리·제거하는 필터링 알고리즘 [8]
- KLA 특허에 "KLA-Tencor가 판매하는 분류 소프트웨어"의 예로 iDO가 명시됨 [22]
- 2007년 Puma 9150 출시 자료에서도 iDO가 "가장 중요한 수율 문제에 자원을 집중하게 해 의미 있는 결과까지 시간을 단축"하는 기능으로 소개됨 [13]

### 4.2 동작 방식 — 결정 트리(Decision Tree)
KLA 특허(US9310320B2, 2013년 우선권)에 따르면 [22]
- 결함마다 계산한 **속성(attribute)** 으로 **결정 트리**를 만들어 비닝과 샘플링을 수행
- 결정 트리는 사용자가 직접 정의하거나 미리 만들어진 것을 사용
- **여러 층의 설계(디자인) 속성**을 넣어 iDO 트리를 구성 → 수율 영향이 다른 결함끼리 서로 다른 bin으로 분리
- 설계 기반 케어 영역과 설계 기반 비닝(DBB)을 함께 쓰면 여러 층의 결함을 검사·비닝 가능

또 다른 KLA 특허에서는 **설계 기반 비닝의 결과를 iDO의 입력으로 넣는** 구성이 나온다 [23].

### 4.3 설계 정보 활용 — 케어 영역
- **pin•point™, super•cell™**: 치명적인 패턴 위치의 수율 결함 감도를 높이는 KLA 특허 기술 (2016년 3900/2930 발표 자료) [9]
- **pixel•point™, nano•cell™**: 서브 픽셀 크기의 케어 영역을 만들어 수율 관련 결함의 포착과 비닝을 개선하는 설계 인지형 알고리즘 (KLA 제품 페이지) [24]
- 2019년 392x/295x 발표 자료도 성능 향상 요인으로 **광대역 플라즈마 조명, 센서 구조, 칩 설계 정보 통합**을 꼽음 [10]

### 4.4 29xx vs 39xx
| 구분 | 29xx | 39xx |
|---|---|---|
| KLA 명칭 | "Gen4" [11] | "Gen5" (3900 발표 당시 명칭) [9][11] |
| 광원 | 광대역 플라즈마, DUV/UV 대역(2930) [9] | 광대역 플라즈마, **SR-DUV(초해상 심자외선)** [9] |
| 특징 | 2900/2905가 DUV~가시광선 영역의 맞춤형 고NA 광대역 대물렌즈를 처음 사용 [17] | 스캐너급 스테이지 정밀도로 **10nm 미만 결함** 광학 검출 [9] |
| 대상 | 모든 공정 층에서 수율 결함 대비를 최적화해 39xx를 보완 [9] | 첨단 로직·최첨단 메모리(≤5–7nm) [17] |
| 속도 | 웨이퍼 한 장 전체 검사 약 1시간 [9] | 웨이퍼 한 장 전체 검사 약 1시간 [9], 시간당 최대 12인치 웨이퍼 2장 [8] |
| 후속 | 295x (2019) [10] | 392x (2019) [10] |

- 392x/295x는 서로 다른 파장 대역을 써서 STI부터 금속 배선, EUV 노광 품질 관리까지 모든 층을 담당 [10]

### 4.5 KLA의 딥러닝 전환
규칙·결정 트리 기반 iDO 이후 KLA 장비·특허에는 딥러닝 기반 분류가 등장한다.
| 사례 | 내용 | 출처 |
|---|---|---|
| eSL10 (2020) | 고객 검사 요구에 맞춰 적응하는 딥러닝 알고리즘 탑재 | [11] |
| Voyager 1035 | **DefectWise** 딥러닝으로 DOI와 패턴 노이즈·뉴슨스를 인라인에서 빠르게 분리 | [14] |
| 특허 US11087449B2 | 2단계 딥러닝 뉴슨스 필터: 1단계 네트워크가 단일 다이 패치에서 금속 그레인 뉴슨스를 거르고, 고해상도 이미지로 학습한 2단계 네트워크가 줄어든 후보에서 뉴슨스를 추가로 제거 | [21] |

### 4.6 처리 흐름 (출처로 확인된 구성만)
```
광학 검사 (29xx/39xx 명시야 BBP, Puma 암시야)
   → 검출: 다이 대 다이 / MDAT 중간값 이미지 비교            [8]
   → 설계 기반 케어 영역 (pin•point, super•cell 등)           [9][24]
   → iDO: 속성·설계 속성 기반 결정 트리로 뉴슨스 제거·비닝     [18][22]
   → 리뷰 장비(eDR7380): 스마트 샘플링, 자동 결함 분류         [9][10]
   → Klarity: 검사·리뷰 데이터를 근본 원인 정보로 분석          [19]
```

## 5. 결함 데이터와 KLARF · 웨이퍼 맵

### 5.1 KLARF (KLA Results File)
- KLA-Tencor가 만든 웨이퍼 결함 검사 데이터 파일 형식이며, 업계 표준 형식으로 쓰임 [26]
- 결함의 **좌표, 분류, 크기** 등이 들어가며, KLA 외의 여러 소프트웨어도 읽고 처리함 [26]
- 오픈소스 파서가 있음: klarfio(파이썬, v1.2·v1.8 읽기/쓰기) [27], klarfrs(러스트, 로트 ID와 다이 안 상대 좌표 xrel/yrel 등을 구조체로 반환) [28]
- → DiePipeline 결함 보고서를 KLARF로 내보낼지 검토할 때 위 파서로 형식을 직접 확인할 수 있음

### 5.2 웨이퍼 맵 패턴 (WM-811K)
- WM-811K: 실제 생산 로트 약 4만 6천 개에서 모은 웨이퍼 맵 811,457장의 공개 데이터셋. 그중 172,950장에 전문가가 패턴 라벨을 붙임 [29]
- 라벨 9종: **Center, Donut, Scratch, Edge-Ring, Edge-Loc, Loc, Near-Full, Random, None** [29]
- 패턴별 원인 예시 [29] — 논문마다 원인 설명이 다르므로 참고용
  | 패턴 | 제시된 원인 |
  |---|---|
  | Center | 비정상 RF 동작, 비정상 액체 흐름 |
  | Edge-Ring | RTP·냉각 공정의 온도 제어 이상 |
  | Edge-Loc | 어닐링 이상, 로드락 밸브 오염 |
- Edge-Loc과 Scratch는 둘 다 가장자리 근처의 길쭉한 뭉침이라 모양이 비슷하지만 원인이 달라서, 헷갈리면 엉뚱한 공정을 고치게 됨 [29]

## 7. 우리 프로젝트(DiePipeline)와의 연결

위에서 확인한 KLA 개념을 DiePipeline 기능에 대응시킨 표. (이 절은 우리 쪽 분석이라 외부 출처 없음)

| KLA 개념 | DiePipeline 대응 |
|---|---|
| 다이 대 다이 / MDAT 중간값 이미지 비교 | 골든 패치 등록 후 다이 비교 |
| 설계 기반 케어 영역 | 영역 저장·불러오기 |
| 비교 전 다이 정렬 | 정합 레시피 |
| 결함 속성 → 결정 트리 비닝(iDO) | 특징 등록 |
| 웨이퍼 맵 | 웨이퍼 실행 실시간 맵 |
| 리뷰 | 다이 미리보기 · 원본 이미지 뷰어 |
| 결함 크기 보고 | 거리 재기 · µm 환산 |
| KLARF | 결함 보고서 |

**참고할 점**
- KLA도 **검출(이미지 차이) → 거르기(속성 기반 결정 트리) → 리뷰** 단계를 나눈다. 우리도 검출 단계와 뉴슨스 필터 단계를 분리해 두면 나중에 필터만 딥러닝으로 바꾸기 쉽다 (KLA가 iDO 이후 DefectWise 등으로 간 흐름).
- MDAT처럼 **여러 다이의 중간값 이미지**를 기준으로 쓰는 방식은 골든 패치 하나에 의존하는 방식의 대안으로 검토할 만하다.
- 결함 보고서에 **다이 인덱스 + 다이 안 좌표 + 크기 + 분류**를 담아 두면 KLARF 형식과 맞추기 쉽다.
