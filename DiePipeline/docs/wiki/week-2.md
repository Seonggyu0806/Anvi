# 2주차 — 파이프라인 한 벌 만들기

> 각자 만들어 보고, 서로 돌려봤다.

---

## 계획했던 것

- 배운 것을 **하나로 이어 붙인다** — 지금까지는 조각만 있고 돌아가는 프로그램이 없었다
- 동기와 **각자** die 검사 파이프라인을 만든다
- 만들고 나서 **서로 돌려본다**

---

## 한 일

### 파이프라인이 처음부터 끝까지 돈다

```
① Combine   이웃 die를 겹쳐 "정상"(골든)을 만든다
② Normalize 골든과 검사본을 같은 조건으로
③ Align     몇 px 어긋난 걸 맞춘다
④ Difference★ 뺀다
⑤ Filter    티끌을 지운다
⑥ Binarize  결함이다 / 아니다
⑦ Label     흰 덩어리를 세어 목록으로
```

여기에 **꼬리 3종**(모양으로 거르기 · 종류 붙이기 · 개수 제한)까지 붙였다.

### 구조는 3층으로

| | |
|---|---|
| **App** | 명령행 |
| **OpenCv** | 실제 알고리즘. OpenCV를 쓴다 |
| **Core** | 칠판 · 엔진 · 레시피. **OpenCV를 모른다** |

순서는 코드가 아니라 **JSON 레시피**가 정한다. 값을 바꾸려고 다시 빌드할 필요가 없다.

**웨이퍼 층은 아직 없다.** die 한 장을 검사하는 데까지가 이번 주의 범위다.

### 실데이터를 처음 돌렸다

깨끗한 구역에서 **오검 0개**. 결함을 심어 보니 **지름 4px까지** 잡았다.

### 사고가 하나 났다 — 정합이 조용히 틀렸다

깨끗한 셀에서 결함이 11개 나왔다. 원인은 ③ Align이었다.

> 무늬가 규칙적이면 "가장 닮은 자리" 가 여러 개다.
> 재는 도구가 **엉뚱한 답을 자신 있게** 낸다. 죽지도, 오류를 내지도 않는다. **답만 틀린다.**

**못 믿을 때 멈추는 가드**를 달아 해결했다. 코드 30줄로 오검 11개가 사라졌다.

### 성능을 반으로 줄였다

`90 ms → 44 ms`. **결과가 안 바뀐 것을 같이 확인**했다.

## 서로 돌려본 결과

| | 이쪽 | 동기 |
|---|---|---|
| 1250×1250 한 번 | 76.6 ms | 1,611 ms |
| 테스트 | 176개 | 212개 |
| 알고리즘 | 7 + 꼬리 3 | 15 |
| 외부 라이브러리 | OpenCvSharp | 없음 (직접 구현) |
| 웨이퍼 층 | 없음 | 있음 |

**한쪽이 낫다기보다 방향이 달랐다** — 이쪽은 깊게(성능·메모리), 동기는 넓게(기능·실데이터).

**기능추가**

| | |
|---|---|
| **노드 끄기** | 레시피에서 단계 하나를 꺼도 뒤가 안 깨지게. 화면의 체크박스와 1:1로 맞는다 |
| **결함 후처리 3종** | 찾아 놓은 목록을 모양으로 거르고 · 종류 붙이고 · 개수를 제한한다 |
| **ECC 정합** | 어긋남을 재는 다른 방법. 반복 무늬에서 덜 헤맨다 |
