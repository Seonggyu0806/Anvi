# 4주차 — 웨이퍼 층

> die 하나를 검사하는 것까지는 됐다. 이제 **"누가 이웃인가"를 아는 층**을 얹는다.
> **진행 중인 주차다.**

---

## 계획했던 것

| | 무엇 |
|---|---|
| **격자** | 원점 · 피치 · 행열 → die 하나하나의 위치 |
| **이웃 고르기** | 이 die의 골든을 누구로 만들까 |
| **웨이퍼 러너** | die 목록을 돌리며 엔진을 부른다 |
| **결함 모으기** | die별 결과 → 웨이퍼 전체 목록 |
| **좌표 변환** | die 안 좌표 → 웨이퍼 절대 좌표 |
| **샘플링** | 전수 검사 대신 일부만 볼 때 어느 die를 볼까 |
| **정렬** | 웨이퍼가 어떻게 놓였는지 찾아내기 |

### 왜 이 층이 필요한가

**die 한 장만으로는 검사가 성립하지 않는다.** 골든을 만들려면 이웃이 필요한데,
**"누가 이웃인가"는 웨이퍼 격자만 아는 정보**다.

> **비유** — 주방(die 검사) 하나로는 식당이 안 굴러간다.
> **홀 매니저**가 "3번 테이블, 7번 테이블…" 하고 주문을 넣어줘야 한다.

---

## 먼저 정한 설계 — die 반복은 **엔진 밖**에 둔다

```
엔진 안에 넣을 수 있는 것    ①→②→③→…    순서가 미리 정해진 것
엔진 안에 못 넣는 것          die N개 반복   N이 실행할 때 정해진다
```

JSON 레시피는 **노드를 몇 개 어떤 순서로** 놓을지를 적는 파일이다.
그런데 die 개수는 **웨이퍼를 열어 봐야 안다.**

> **비유** — 레시피에 "양파를 볶는다 → 고기를 넣는다" 는 적을 수 있다.
> 그런데 **"손님 수만큼 반복한다"** 는 못 적는다. 손님 수는 그날 정해진다.
> 그건 **홀 매니저가** 한다.

```
Wafer 층 (바깥)     die 목록을 만들고, 하나씩 돌린다
    │
    └─ 각 die 마다 ─→  Core 엔진 (안쪽)   레시피대로 ①→②→…→⑦
```

**Lesson16도 교수님 구현도 같은 결론이었다.** 우연이 아니라 문제의 성질이다.

## ✅ 한 일 — 격자

```
Wafer/
 ├ Domain/Wafer.cs               WaferZone · DieOrigin · DieGrid · WaferAlignment
 ├ Config/WaferSpec.cs           웨이퍼 형상
 └ Execution/DieGridBuilder.cs   형상 + 정렬 → die 원점 격자
```

### E1 / E0 존 — 가장자리를 따로 본다

| | |
|---|---|
| **E1** | 안쪽. 이웃이 사방에 다 있다 |
| **E0** | 가장자리. **이웃이 모자라다** |

몇 겹을 가장자리로 볼지 정할 수 있다.

```
rings 0        rings 1        rings 2
11111          00000          00000
11111          01110          00000
11111          01110          00100
11111          01110          00000
11111          00000          00000
        1 = E1 (안쪽)   0 = E0 (가장자리)
```

### 웨이퍼가 삐뚤게 놓였을 때

웨이퍼는 장비에 **정확히 반듯하게** 놓이지 않는다. 그래서 격자를 두 단계로 만든다.

```
①  이상적인 자리          원점 + 열×피치, 원점 + 행×피치
②  실제로 놓인 대로 변환   회전 + 확대/축소 + 이동
```

**1도만 기울어도 300px 떨어진 끝에서는 5px이 밀린다.**
2~3px만 어긋나도 모든 경계에 띠가 남으니 반드시 보정해야 한다.

### 값이 이상하면 멈춘다

| 거부 | 왜 |
|---|---|
| 열·행이 0 이하 | 격자가 아니다 |
| 피치가 0 이하 | 모든 die가 같은 자리에 겹친다 |
| die 크기 > 피치 | ROI가 서로 겹친다 |
| 확대율 0 | **모든 좌표가 원점으로 무너진다** |

마지막 것이 특히 중요하다. 확대율 0이면 **오류가 안 나고 모든 die가 (0,0)에 놓인다.**
2주차에 겪은 "조용히 틀리는 실패" 바로 그 모양이라 미리 막았다.

### 이름은 교수님 것을 따랐다

`WaferZone` · `DieOrigin` · `DieGrid` · `WaferAlignment` · `WaferDefect` · `DieResult` —
전부 교수님 레포와 같은 이름이다.

> **서로 교차 참조할 수 있어야 하기 때문이다.**
> 2주차에 "서로 코드를 못 읽었다" 를 겪었으니, 이번엔 이름부터 맞춰 둔다.

## 🔨 남은 것

이웃 고르기 · 웨이퍼 러너 · 결함 모으기 · 좌표 변환 · 명령행 `wafer` · 샘플링 · 정렬

### 이웃 고르기에는 3주차 측정이 그대로 들어간다

**이웃 고르는 법과 합치는 법이 짝**이라는 것을 쟀으니,
둘을 **같이** 정할 수 있는 모양으로 만든다.

### 정렬이 제일 어려울 것으로 본다

웨이퍼에 찍힌 표식을 찾아 **어떻게 놓였는지**를 역산한다.
2주차에 "정합이 조용히 틀린다" 를 겪었으니 **여기도 가드가 필요할 것**이다.
