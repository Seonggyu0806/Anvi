# 5주차 — 화면(WPF)과 원형 웨이퍼 가장자리 검사

`2026-09-25 ~ 10-02`

## 요약

1. 화면(WPF)을 만들었다 — die 탭(블록 편집 · 미리보기 · 슬라이더)과 웨이퍼 탭(웨이퍼 맵)
2. 화면에서 실데이터를 돌리며 드러난 오류 4가지를 고쳤다
3. 원형 웨이퍼의 가장자리 die(E0)를 검사하게 만들고, 원판 전체를 찍은 실데이터로 확인했다
4. 큰 원본에서도 정렬이 동작하도록 표식 근처만 읽게 바꿨다

## 한 일

### 1. 화면(WPF)

| 탭 | 기능 |
|---|---|
| die 탭 | 레시피를 블록으로 편집 · 열기/내보내기 · 단계별 중간 결과 · 결함 표시 · 임계값 슬라이더 |
| 웨이퍼 탭 | 합성 웨이퍼 또는 이미지 파일 검사 · 웨이퍼 맵(깨끗함 · 결함 · 실패를 색으로 구분) · 정렬 결과 · die별 결함 목록 |

- 노드 끄기: 레시피 파일을 바꾸지 않고 단계를 실행에서 뺀다. 꺼진 단계는 입력을 그대로 출력으로 넘긴다(입력 · 출력이 1개인 단계만)
- 슬라이더: 미리보기 한 번이 1~3 ms라 부분 재실행 없이도 끊기지 않는다
- 웨이퍼 검사 흐름과 합성 웨이퍼 생성을 명령행 밖(Wafer · Cv 층)으로 옮겨, 명령행과 화면이 같은 코드를 쓴다
- 판단 로직은 화면(ViewModel) 밖에 두어 화면 없이 테스트한다

### 2. 실데이터에서 드러난 오류 수정

넷 다 프로그램은 정상 종료하지만 결과가 틀리는 오류였다.

| 증상 | 원인 | 수정 |
|---|---|---|
| 결함 0개 | 웨이퍼 탭이 미리보기용 기본 레시피를 썼다 | 결과에 실제로 쓴 레시피 이름을 표시 |
| 사진 일부만 검사 | 격자 값이 합성용 그대로였다 | 격자가 사진을 다 덮지 않으면 경고 |
| 결함 3개가 4개로 | 이웃 두 die의 결함이 겹치면 Median 골든에도 결함이 들어가 검사 die에 되비친다 | 차이 부호가 Absolute면 경고 — 결함이 어두우면 DarkOnly를 쓴다 |
| 주석 오류 | 레시피 이름을 파일 이름처럼 적었다 | 수정 |

### 3. 원형 웨이퍼 E0 존

- 지금까지 실데이터는 웨이퍼 안쪽만 찍어 E0가 없었다. 원판 전체를 찍은 원본으로 가장자리를 검사했다
- 원판(중심 · 반지름)을 넣으면 칸을 셋으로 나눈다: 원판 안 = E1, 원판에 걸침 = E0, 원판 밖 = 검사하지 않음
- E0 die에는 원판 밖 배경까지 찍혀 배경이 결함으로 잡힌다 → E0 레시피 앞에 원판 밖을 가리는 단계(MaskApply)를 둔다. 교수님 설계의 MaskApply를 따랐다
- 가장자리 여유(edge exclusion): 원판 가장자리에서 일정 폭은 검사하지 않는다. 원을 맞춘 오차와 노치(원판의 홈)를 가린다
- 버그 수정: 사진 밖으로 잘린 die에서 결함의 절대 좌표가 밀리던 문제
- 원형 합성 웨이퍼를 만들어 정답과 비교하는 시험을 붙였다

| 가장자리 여유 | 실데이터 결과 |
|---|---|
| 0 | E0에서 원 가장자리의 가는 호 + 노치를 결함으로 검출 |
| 피치의 1% 미만 | 노치만 남음 |
| 피치의 6% | 0개 |

- 모든 die를 검사했고 검사 실패 0, E1 결함 0
- 한계: 이 원본에는 정답(심은 결함)이 없어, E0 안쪽의 진짜 결함 검출은 합성 시험으로만 확인했다

### 4. 정렬 창

- 정렬이 표식을 찾으려고 원본 전체를 읽어서 큰 원본(수 GB)에서는 쓸 수 없었다
- 대략 원점 + 표식의 설계 위치 주변의 작은 창만 읽게 바꿨다(교수님 설계 Phase5 #5.10)
- 실데이터: 원본의 1% 미만만 읽고 원점을 찾았다. 손으로 잰 값과 수 px 차이이고 검사 결과는 같았다
- 한계: 표식이 die마다 반복되면 대략 원점이 피치의 절반 안에 있어야 한다
