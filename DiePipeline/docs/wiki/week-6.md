# 6주차 — 웨이퍼 입력 보완과 웨이퍼 레시피

`2026-10-02 ~ 10-09`

## 요약

1. 원본(raw)을 BMP 로 바꾸지 않고 직접 읽는다
2. 원 판정이 틀리는 die(노치)를 사람이 지정해 검사에서 뺀다
3. 결함 목록에서 하나를 고르면 원본 해상도로 그 자리를 보여 준다
4. 명령행에서만 되던 정렬 · 수동 지정 · 원판 마스크를 화면에서도 입력한다
5. 미뤄 둔 실험 3개를 했다 — 밝은 결함 · die 전체 결함 수 · 정렬 결정성
6. 웨이퍼 검사 설정을 파일 하나(웨이퍼 레시피)로 적고 돌린다
7. 위키 1~5주차를 다시 쓰고 문서를 정리했다

## 한 일

### 1. raw 직접 읽기

- 실데이터는 raw 파일과 설명 파일(`<원본>.raw.json` — 폭 · 높이 · 픽셀당 바이트 · 행 순서)로 온다
- 설명 파일이 있으면 raw 로 열고, 파일 크기가 폭 × 높이 × 픽셀당 바이트와 다르면 거부한다
- 설명 파일의 키 이름은 교수님 구현과 같다
- 같은 원판의 BMP 로 돌린 결과와 raw 로 돌린 결과가 같았다

### 2. die 수동 지정

- 원판(원)으로 판정하면 노치(원판의 홈)에 걸린 die 를 온전한 die 로 본다
- 사람이 die 하나의 존을 정한다: `열,행=E1|E0|off`. off 는 그 die 를 검사와 이웃에서 뺀다
- 자동 판정 뒤에 덮어쓴다. 격자 밖 · 중복 지정은 실행 전에 거부한다. 결과 머리에 지정 목록을 찍는다
- 교수님 문서의 "수동 오버라이드 목록"을 따랐다
- 실데이터: 노치 die 2칸을 빼자 가장자리 결함이 0개가 됐다

### 3. 결함 원본 보기

- 결함 위치는 die 안 좌표라, 사진 위 자리 = die 위치 + 결함 위치로 계산한다
- 보여 주는 창은 결함 긴 변의 4배, 128~1024 px 로 제한하고 사진 밖으로 나가지 않게 민다

### 4. 화면 입력

- 웨이퍼 탭에 정렬 표식(조각 · 설계 위치 · 찾는 범위)과 수동 지정 입력칸을 넣었다
- die 탭 미리보기도 원판 마스크를 받는 레시피를 돌릴 수 있게 했다
- 글자 입력 규칙(점 · 수동 지정)을 한 곳에 두어 명령행과 화면이 같은 규칙으로 읽는다
- 화면에서 실데이터로 돌려 명령행과 같은 결과를 확인했다

### 5. 미뤄 둔 실험

| 실험 | 결과 |
|---|---|
| 밝은 결함 | 기본 레시피(평균 + 어두운 쪽만)는 밝은 결함을 못 보고, 이웃이 1장인 끝 열 die 에 어두운 오검을 만든다. 대안 레시피(중앙값 + 양쪽)는 밝은 결함을 찾지만, 이웃 2장의 결함이 겹친 자리에서 오검이 난다. 지름 약 25 px 보다 작은 결함은 두 레시피 모두 면적 기준(500)에서 버려진다 |
| die 전체 결함 수 | 3주차 집계는 die 일부만 본 값이었다. die 전체로 보면 교수님 기준 결과와 같은 수다 |
| 정렬 결정성 | 같은 입력으로 30번 돌려 표식 위치 · 원점 · 각도가 소수 17자리까지 같았다 |

### 6. 웨이퍼 레시피

- 격자 · 원판 · 수동 지정 · 정렬 표식을 명령줄에 매번 적지 않고 파일 하나(`*.wafer.json`)에 적는다
- 파일은 블록 5개를 이은 것이다: 표식 찾기 → 자세 계산 → die 전부 검사 → 웨이퍼 좌표 → 결과 추리기. 교수님 구현과 이름 · 구조가 같다
- 엔진은 블록을 한 번씩만 실행한다. 표식 찾기는 표식마다, die 검사는 die 마다 반복해야 하므로 실행기가 레시피를 나눠 실행한다
- 명령행 옵션으로 돌리든 레시피 파일로 돌리든 같은 검사 흐름을 지나며, 두 방법의 결과가 같은지 시험한다
- 실행: `diepipe wafer -i <사진> --recipe <웨이퍼레시피>`. 견본 레시피와 합성 웨이퍼로 심은 결함 3개를 그 die 에서 찾는다
- 화면에서 블록으로 짜는 편집기는 미팅에서 정한다

### 7. 문서

- 위키 1~5주차를 다시 썼다 — 맨 위 요약 · 코드 없이 읽히게 · 비유 없이
- 지난 구현(v1) 문서를 정리하고 미룬 것 · 할 일 · 안내서로 나눴다
