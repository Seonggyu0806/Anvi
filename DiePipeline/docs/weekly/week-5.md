## 1. 왜 화면이 필요한가

검사 프로그램의 값은 **책상에서 정할 수 없다.** 3주차에 그걸 겪었다.

```
임계값 0.12 ~ 0.30 → 결과가 전부 같다
minArea 5 → 500    → 오검 476개가 사라진다
```

**어느 손잡이가 듣는지는 돌려 봐야 안다.** 그런데 지금은 한 번 돌릴 때마다
명령을 다시 치고 숫자를 읽어야 한다.

> **비유** — 라디오 주파수를 맞추는데 다이얼이 없고
> "95.7 을 입력하고 전원을 껐다 켜세요" 만 있는 것과 같다.
> **돌려가며 듣는 것**이 다이얼이다.

## 3. 1주차에 배워 둔 것 — MVVM

Lesson08에서 만들어 본 것들이 그대로 재료다.

```
MainViewModel       화면이 보여줄 값과 명령
RelayCommand        버튼 하나 = 객체 하나
ObservableObject    값이 바뀌면 화면에 알린다
IDialogService      대화상자를 인터페이스로 빼 둔다
BitmapConvert       OpenCV 이미지 → 화면이 그릴 수 있는 형식
```

**`IDialogService` 를 인터페이스로 빼 두는 이유**가 이 중에 제일 중요하다.

> "파일을 못 열었습니다" 대화상자가 코드에 박혀 있으면 **테스트를 돌릴 수가 없다** —
> 테스트 중에 창이 떠서 사람이 누를 때까지 멈춰 버린다.
> 인터페이스로 빼 두면 테스트에서는 **"눌렀다고 치는 가짜"** 를 끼워 넣으면 된다.

## 4. 미리 확인해 둔 것 — 2주차 점검에서

WPF를 얹고 나면 아래층을 고치기 어렵다. 그래서 **얹기 전에** 세 가지를 확인해 뒀다.

### ① 느리면 슬라이더를 못 만든다

슬라이더를 드래그하면 **초당 수십 번** 검사가 돈다.

| 합성 die 크기 | 전체 실행 | 부분 재실행 | |
|---|---|---|---|
| 1024×1024 | 86.1 ms | **4.1 ms** | 21배 |
| 2500×2500 | 536.5 ms | **22.0 ms** | 24배 |

**임계값을 바꿨을 때 실제로 달라지는 것은 뒤의 두 단계뿐**이다.

```
Combine → Normalize → Align → Difference → Filter │ Binarize → Label
└──────── 임계값과 무관. 지난 결과를 그대로 쓴다 ────┘ └─ 이것만 다시 ─┘
```

앞을 다시 안 돌면 **21배**가 빨라진다.

> 2주차에 "1024×1024 44 ms" 라고 적은 것과 여기 86.1 ms 는 **다른 설정**이다.
> 44 ms 는 실데이터 타일에 노드 8개, 86.1 ms 는 합성 die에 노드가 더 많은 레시피다.
> **시간을 적을 때는 무엇을 어떻게 쟀는지 같이 적어야 한다.**

> **답이 같은지부터 확인했다.** 부분 재실행과 전체 실행의 결함을 면적·중심까지 대조했다.
> **빨라지려고 답이 달라지면 아무 의미가 없다.**

⚠ **이 구조는 v2에 안 들어가 있다.** 3주차 규칙(배운 범위 안에서만) 때문에 뺐다.
슬라이더를 만들 때 **다시 필요해지면 그때 넣는다** — 그때는 "왜 넣는지" 에 답할 수 있다.

### ② 예외가 나도 메모리를 놓아야 한다

화면에서는 **잘못된 입력이 계속 들어온다.** 파일을 잘못 고르고, 값을 이상하게 넣는다.
예외가 날 때마다 메모리를 안 놓으면 **쓸수록 무거워진다.**

| | 전 | 후 |
|---|---|---|
| 예외 경로 메모리 누수 | 9곳 | **0** |
| 100회 반복 시 메모리 증가 | — | **없음** (테스트로 고정) |

### ③ 오류 메시지가 사람 말이어야 한다

명령행에서는 예외 이름이 그대로 떠도 된다. **화면에서는 안 된다.**

```
❌  System.ArgumentOutOfRangeException: Specified argument was out of...
✅  이미지 크기가 서로 다릅니다 (1024×1024 와 512×512)
```

그래서 예외 타입을 사용자에게 보이지 않도록 정리해 뒀다.

## 5. 화면이 쓸 자리는 이미 있다

| 화면이 필요한 것 | 지금 있는 것 |
|---|---|
| 각 단계가 얼마나 걸렸나 | 엔진이 단계별 시간을 낸다 |
| 각 단계의 중간 이미지 | **칠판에서 이름표로 꺼낸다** — 따로 만들 필요가 없다 |
| 노드 끄기 체크박스 | 레시피의 "끄기" 와 **1:1 대응**되게 만들어 뒀다 |
| 취소 | 취소 토큰이 파이프라인을 관통한다 |

**칠판 구조가 여기서 값을 한다.** 중간 결과를 보려고 따로 저장할 필요가 없다 —
이미 이름표를 달고 칠판에 올라가 있기 때문이다.

> 2주차에 동기 구현과 비교하면서 **"이건 나중에 못 넣는다"** 고 판단했던 것들이
> 전부 이 자리에서 쓰인다.

## 6. 예상되는 어려움

| | |
|---|---|
| **큰 이미지를 화면에 어떻게** | 원본은 통째로 못 올린다. 3주차의 부분 읽기를 화면 확대/축소에 연결해야 한다 |
| **드래그 중 취소** | 슬라이더를 끌면 이전 실행이 아직 도는 중이다. 취소하고 새로 시작해야 한다 |
| **웨이퍼 맵의 크기** | die가 수백 개면 네모 수백 개를 매번 다시 그릴 수 없다 |

---

## 7. 완료 기준

1. 이미지와 레시피를 열어 **버튼 하나로** 검사가 돈다
2. 결함이 원본 위에 **네모로** 표시된다
3. 임계값 슬라이더를 끌면 **끊김 없이** 결과가 따라온다
4. 잘못된 입력에 **사람이 읽을 수 있는 메시지**가 뜬다
5. 화면 없이 **ViewModel만으로 테스트가 돈다**

5번이 제일 중요하다. **화면을 띄워야만 확인할 수 있는 코드는 나중에 고칠 수가 없다.**
